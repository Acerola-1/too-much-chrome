# Too Much Chrome 上线前收尾计划（基于 dev 分支）

## 背景与结论
- 代码审查已完成：无 TODO/FIXME/注释掉的代码块；注释为中文、多数承载实测事实（保留），但存在复述性头部注释（删除）；核心逻辑（检测分层、版本带、体积统计）质量良好。
- 发现的问题：死代码 `AppType.light`、`GlassGroup`（Theme.swift）；GUI 与 CLI 状态判定逻辑重复（displayStatus vs statusMark）；`healthCounts` 每帧 5 次全量 filter；`.app` 打包**未嵌入应用图标**（上线前必修）；`Model.swift` "绿/绿" 注释笔误。
- 分支策略（按你的决定）：main 先提交待审的图标迁移 → 从 main 拉 dev → **全部收尾工作分 commit 落在 dev，不 push、不合并 main**。以后开发都在 dev，发布时经 release 脚本进 main。
- 参照 hagimi-monitor 实现：三语 README（zh/en/ja 三文件）、官网（docs/ 目录 + zh/en/ja 页面 + 自动语言重定向）、scripts/release.sh 发布脚本（tag 推送触发 Actions）、release.yml（macos-26 + 证书导入 + 公证 + DMG + 部署 gh-pages）、AGPL-3.0 双许可。

## Phase 0 — Git 基线（main）
1. `git add -A` 提交当前待审迁移（63 个 icon-prototypes 删除 + AppIcon.icon/ + legacy-assets/），commit：`chore: 图标工作坊归档至 legacy-assets，最终图标定稿 AppIcon.icon`。
2. `git checkout -b dev` 拉出开发分支，后续全部工作在此分支。

## Phase 1 — 代码质量收尾（dev）
- **注释精简**：删除复述性头部注释（ContentView、AppScanner、VersionCatalog、Theme、tmc-scan 顶部说明块），保留承载非显然事实的注释（如 QQNT.framework 保留 Electron Bundle ID、Tauri 版本塞入应用版本等）；修 "绿/绿" 笔误。
- **删死代码**：`AppType.light`、`GlassGroup`（全仓库唯一引用即定义处）。
- **DRY**：把 `displayStatus` 判定下沉到 Core（`VersionBands.status(for:latest:)` 或等价），GUI 与 tmc-scan 共用，删除 tmc-scan 内重复的 switch。
- **性能**：`healthCounts` 改为单次遍历 `Dictionary(grouping:)`；GlassSegmentedFilter 分段计数改用 model.typeCounts；图标加载移入 `Task.detached`（主线程只做字典写入）；donut 小分段 guard（避免负弧度）。
- **验证**：`swift build` + `swift test` + `tmc-scan` 无头跑通 + GUI 后台启动 liveness（CGWindowList bounds + screencapture 存图供你复查，本会话模型无法读图，我会以文件大小/窗口存在性佐证）。

## Phase 2 — 目录精简与归档（dev）
- `too-much-chrome.design/` 整体迁入 `legacy-assets/too-much-chrome.design/`（含 pages、css、mapping、preflight、两个 json、design.design），`detection-strategy.md` 保留根目录（代码注释引用的活 spec）。
- `LoadingConcepts/` 整体迁入 `legacy-assets/LoadingConcepts/`（已选定并实装的扫描线⑥除外）。
- 清理根目录 `.DS_Store` 等杂物；更新 legacy-assets/README.md 内容清单。
- 最终标准结构：`Package.swift / Sources/ / Tests/ / scripts/ / docs/ / .github/ / AppIcon.icon/ / legacy-assets/ / README*.md / README 三语 / launch.sh / detection-strategy.md / LICENSE`。

## Phase 3 — 应用图标接入打包（dev）
- 新增 `scripts/render_icon.swift`：合成 AppIcon.icon/Assets/background-dark.png（碳黑最终版）+ front.png → 1024 flat master.png → CoreGraphics 下采样出 iconset 各尺寸 → `iconutil -c icns` 产出 AppIcon.icns。
- `scripts/build-app.sh` 增强：组装 .app 时生成并嵌入 `Contents/Resources/AppIcon.icns`，Info.plist 加 `CFBundleIconFile`。dev/release/dmg 三种模式统一生效。
- 验证：检查构建产物 .app 内含 AppIcon.icns + plist 键正确。

## Phase 6 — 发布流水线（dev）
- 新增 `scripts/release.sh`（仿 hagimi，适配 SwiftPM）：`./scripts/release.sh <x.y.z> [-n/-f/-o/-c/-m ...]` → 校验版本与 gh 登录 → 工作区干净检查 → sed 提升 `scripts/build-app.sh` 的 VERSION → 生成 RELEASE_NOTES.md（分类模板）→ `release/<v>` 分支 → PR→main（squash 合并）→ `git tag v<v>` 推送（**触发 Actions**）→ 切回 dev 同步 main（自动解决 build-app.sh + RELEASE_NOTES.md 冲突 --theirs）。
- 升级 `.github/workflows/release.yml`：`runs-on: macos-26`（与本地 Xcode 26 一致）→ hagimi 式证书导入（MACOS_CERT_P12 / MACOS_CERT_PASSWORD / SIGN_IDENTITY / TEAM_ID / APPLE_ID / NOTARY_PASSWORD secrets）→ `./scripts/build-app.sh dmg`（签名+公证+DMG，图标已嵌入）→ `gh release create`（附 RELEASE_NOTES.md + DMG）→ `peaceiris/actions-gh-pages` 部署 docs/ 到 gh-pages（官网上线）。
- 本地演练：`release.sh` 帮助/参数校验/干净树检查等 dry 检查；真实发布留待你配置 secrets 后执行。
