Too Much Chrome

看看你的 Mac 里藏了多少网页引擎应用

Too Much Chrome 扫描 macOS 上所有基于 Chromium / WebView 的应用——Electron、CEF、NW.js、Tauri、Wails，以及 Chrome、Edge、Brave 这类完整浏览器——并统计它们占用的存储空间与版本健康度。

下载最新版 查看源码

功能亮点扫描是认真的——体积、版本、健康度，一次看清

🔍

真实扫描

枚举 /Applications 与 ~/Applications 顶层 .app。Electron / CEF / NW.js 按框架目录与 plist Bundle ID 特征识别，接近 100% 准确率；Tauri / Wails 走实验性关键词检测。

💾

体积统计

应用本体递归计算分配大小，加上 ~/Library 用户数据（Application Support / Caches / Containers），按 bundle id 与应用名双重匹配并去重。

🩺

版本健康度

按在线版本基准（Electron / Chromium / Tauri / Wails 官方源）动态分档五档状态，绿到红一眼可辨；离线时退内置锚点。

📠

扫描线开场

复印机扫描线绑定真实扫描进度——光条位置即扫描进度，图标按发现顺序逐个去模糊显现，动画即进度。

📊

报告面板

总数、存储占用（本体 vs 数据）、类型分布环形图、Top 5 存储排行与版本健康度，右侧玻璃面板一屏尽览。

🖱️

详情弹层

点击任意应用查看存储分解与安装路径，一键在 Finder 中显示；排行行与网格图标联动高亮，⌘R 随时重扫。

检测分层不同框架的可信度不同，检测策略如实标注

Tier 1 · 高准确率

Electron / CEF / NW.js

Contents/Frameworks 框架目录名与 plist Bundle ID 双特征。改名构建（如 QQNT.framework）仍保留 com.github.Electron.framework，是目录名之外的第二特征。

Tier 2 · 实验性

Tauri / Wails

Bundle ID 与资源目录关键词，主二进制内的构建路径特征兜底。依赖开发者命名规范，Wails 经 garble 混淆后无法识别（已知局限）。

Tier 3 · 仅列出

完整浏览器

Chrome / Edge / Brave / Arc / Vivaldi / Opera 等 Chromium 系浏览器仅列出，按应用主版本对 Chromium 基准分档；版本方案不对齐的从主二进制 UA 串兜底提取。

拖入 Applications

3

启动

从 Launchpad 或 Applications 启动，首次扫描自动开始

macOS 14 及以上 Apple Silicon（M 系列芯片） Apple 公证 · 可离线使用

构建SwiftPM 工程，macOS 26 上自动启用液态玻璃

开发启动

# 一键构建 .app 并启动（内部走 scripts/build-app.sh dev）
./launch.sh
./launch.sh cli  # 无头扫描 CLI（tmc-scan）

构建与测试

swift build
swift test
swift run tmc-scan --online

也可用 Xcode 直接打开 Package.swift 运行。对外分发（签名 + 公证 + DMG）走 scripts/build-app.sh。
