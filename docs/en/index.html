Too Much Chrome

See how many web-engine apps are hiding on your Mac.

Too Much Chrome scans every Chromium / WebView app on your macOS — Electron, CEF, NW.js, Tauri, Wails, and full browsers like Chrome, Edge, and Brave — then measures how much storage they take and how current their engines are.

ScreenshotsA floating glass toolbar and the report panel on one line

HighlightsStorage, versions, and health — everything in one scan

🔍

Real Scanning

Enumerates top-level .app bundles in /Applications and ~/Applications. Electron / CEF / NW.js are identified by framework directory and plist Bundle ID — near 100% accuracy; Tauri / Wails use experimental keyword detection.

💾

Storage Statistics

Recursive allocated size of the app bundle plus user data under ~/Library (Application Support / Caches / Containers), matched by bundle ID and app name with deduplication.

🩺

Version Health

Five-tier status judged against an online baseline from official sources (Electron / Chromium / Tauri / Wails), with built-in anchors as offline fallback. Green to red at a glance.

📠

Scanline Intro

A photocopier-style scanline bound to real scan progress — the light bar position is the progress, and icons unblur one by one as they are discovered. Animation is progress.

📊

Report Panel

Total count, storage split (app vs data), a type-distribution donut chart, top-5 storage ranking, and version health — all in one glass panel on the right.

🖱️

Detail Popover

Click any app to see storage breakdown and install path, reveal it in Finder with one click; ranking rows and grid icons highlight in sync, and ⌘R rescans anytime.

Detection TiersEach framework has a different confidence level, and the strategy says so

Tier 1 · High accuracy

Electron / CEF / NW.js

Dual signals from Contents/Frameworks directory names and plist Bundle IDs. Renamed builds (e.g. QQNT.framework) still keep com.github.Electron.framework as a second signal.

Tier 2 · Experimental

Tauri / Wails

Bundle ID and resource-directory keywords, with build-path signatures inside the main binary as a fallback. Depends on developer naming conventions; Wails builds obfuscated by garble are undetectable (known limitation).

Tier 3 · Listed only

Full Browsers

Chromium-based browsers — Chrome, Edge, Brave, Arc, Vivaldi, Opera — are listed and scored against the Chromium baseline; builds with divergent versioning fall back to a "Chrome/x.y.z.w" UA string in the binary.

Download the DMG

Grab the latest TooMuchChrome-<version>.dmg from GitHub Releases

2

Drag into Applications

Open the DMG and drag Too Much Chrome into the Applications folder

3

Launch

Start it from Launchpad or Applications; the first scan begins automatically

macOS 14 or later Apple Silicon (M-series chips) Notarized · works offline

BuildSwiftPM project, Liquid Glass enabled automatically on macOS 26

Development

# Build the .app and launch (runs scripts/build-app.sh dev)
./launch.sh
./launch.sh cli  # headless scan CLI (tmc-scan)

Build & Test

swift build
swift test
swift run tmc-scan --online

You can also open Package.swift in Xcode and hit Run. Distribution (signing + notarization + DMG) goes through scripts/build-app.sh.
